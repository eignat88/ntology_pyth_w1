# Order Analyzer (Batch CSV Processing)

## Краткое описание проекта
`Order Analyzer` — это небольшой CLI-инструмент на Python для пакетной обработки CSV-файлов с заказами интернет-магазина.

Скрипт:
- ищет все `*.csv` в папке `data/`;
- проверяет обязательные колонки;
- допускает в файле набор валидных статусов заказа и отбирает в метрики только `Delivered`;
- считает метрики по каждому файлу (`total_revenue`, `average_check`, `orders_count`);
- формирует единый отчёт `reports/summary_report.csv`;
- пишет ошибки обработки в `logs/errors.log`.

Проект рассчитан на аналитиков, стажёров, data/ops-специалистов и backend-разработчиков, которым нужен простой офлайн-пайплайн для регулярной сверки заказов.

## Требования

### Python
- Python **3.10+** (используются современные type hints, например `dict | None` и `list[str]`).

### Зависимости
- `pandas` (указан в `requirements.txt`).

### ОС и ограничения
- Поддерживаются Linux/macOS/Windows (код кроссплатформенный, пути на `pathlib`).
- Входные файлы должны быть в кодировке/формате, корректно читаемом `pandas.read_csv`.
- Обязательные колонки должны присутствовать во всех входных CSV.
- Используется **строгий режим** валидации суммы: любое пустое или нечисловое значение в `total_amount` делает файл невалидным; файл полностью пропускается и попадает в лог ошибок.

## Установка
1. Клонируйте репозиторий и перейдите в директорию проекта:

```bash
git clone <repo-url>
cd ntology_pyth_w1
```

2. Создайте и активируйте виртуальное окружение:

```bash
python -m venv .venv
source .venv/bin/activate      # Linux/macOS
# .venv\Scripts\activate      # Windows (PowerShell/CMD)
```

3. Установите зависимости:

```bash
pip install -r requirements.txt
```

4. Подготовьте входные данные:
- создайте папку `data/` в корне проекта;
- положите туда CSV-файлы заказов.

## Quick Start
Минимально воспроизводимый сценарий:

```bash
python run.py
```

После запуска:
- в `reports/summary_report.csv` появится итоговый отчёт;
- в `logs/errors.log` появятся ошибки по некорректным файлам (если есть);
- в консоль выведется сводка (`total_files`, `processed_files`, `error_files`).

## Ограничения, Known Issues, Roadmap

### Ограничения
- По умолчанию ищутся только файлы `*.csv` в **корне** папки `data/` (без рекурсии по подпапкам).
- Отчёт агрегируется на уровне «одна строка = один файл», а не по каждому заказу.
- Используется строгий режим для `total_amount`: если в файле есть хотя бы одно пустое или нечисловое значение суммы, метрики по этому файлу **не считаются**, файл целиком помечается как ошибочный и записывается в `logs/errors.log`.
- Значения статуса нормализуются (обрезаются пробелы и игнорируется регистр) перед проверкой.
- В одном файле могут встречаться разные валидные статусы (`refunded`, `returned`, `delivered`, `processing`, `pending`, `cancelled`, `shipped`), но в итоговые метрики попадают только заказы со статусом `Delivered`.

### Known Issues
- Если `data/` отсутствует или пуста, отчёт будет создан пустым (без строк метрик).
- При очень больших CSV отсутствуют оптимизации по памяти (чтение идёт целиком через `pandas.read_csv`).

### Roadmap
- Добавить рекурсивный обход `data/**.csv`.
- Добавить CLI-аргументы (пути, статус, названия колонок) через `argparse`.
- Добавить unit-тесты и CI-проверки.
- Добавить режим стриминговой/чанковой обработки больших файлов.
